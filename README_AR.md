# دليل محاضرات المساق

الجامعة الإسلامية بغزة — كلية تكنولوجيا المعلومات · MOBC 2101.
إعداد: م. محمد أنور الزرد — مدرس المساق.

## التشغيل

افتح `index.html` مع إبقاء مجلدي `assets` و`downloads` بجانبه. لا يحتاج الموقع تثبيت مكتبات أو خادمًا. التنزيلات والروابط الرسمية تحتاج الإنترنت.

## رحلة الطالب

عند فتح الموقع تظهر صفحة ترحيب وبطاقات المحاضرات. البطاقة المتاحة حاليًا هي **L01 — إعداد Android Studio وتشغيل أول كود Kotlin**. جميع الخطوات والمساعدة والمصادر الحالية تخص هذه المحاضرة.

داخل L01 يوجد مسار من تسع خطوات: المواصفات، تثبيت Android Studio، التشغيل الأول، SDK، المحاكي أو الهاتف، فحص الجاهزية، Java المرفقة، تثبيت أو تحديث Scoop وKotlin، ثم إنشاء المجلد وملف main.kts يدويًا وتشغيله من تيرمينال Android Studio.

افتح بطاقة المحاضرة، ثم ابدأ من زر «ابدأ من الصفر» واتبع «التالي». يوجد انتقال مباشر للخطوات، وحفظ للتقدم في المتصفح، وبحث في المشكلات. VS Code قسم اختياري بعد اكتمال المسار.

Java المطلوبة (JDK) تأتي مع Android Studio؛ لا يحتاج الطالب تنزيلها منفصلة. الخطوة 7 تضبطها، والخطوة 8 تثبّت Scoop وGit عند الحاجة ثم Kotlin. الأوامر الطويلة قابلة للفتح للقراءة، وزر النسخ ينسخها كاملة.

أوامر Kotlin في PowerShell العادي. أوامر فحص وتفعيل Windows Hypervisor Platform وحدها موسومة بأنها تحتاج مسؤولًا. الصفحة تنسخ الأوامر فقط؛ لا تنفذها على جهاز الطالب.

## النشر

في GitHub Pages اختر Settings → Pages → Source → GitHub Actions. ملف `.github/workflows/pages.yml` يختبر المشروع ثم ينشر ملفات الطلاب فقط من مجلد `_site` عند رفع التغييرات إلى `main`. ملفات التوثيق والاختبارات تبقى في المشروع، ولا تُنشر على رابط الموقع.

للاستضافة الأخرى، نفّذ `npm run prepare:site` وارفع محتويات `_site` فقط. لا ترفع جذر المشروع كاملًا إلى خادم الطلاب. لا يحتاج الموقع نفسه Node.js؛ يُستخدم هنا لتجهيز نسخة النشر.

زر «رابط الخطوة» يستخدم عنوان النسخة المفتوحة بعد استضافتها. عند فتح ملف محلي، يطلب فتح النسخة المستضافة حتى لا ينسخ مسار جهازك. الروابط الداخلية مثل `#step-1` و`#kotlin-1` محفوظة.

## تعديل المحتوى

- `assets/content.js`: الشرح العربي والإنجليزي، الأوامر والمصادر.
- `assets/guide.js`: فهرسة الصفحات، المسارات وحفظ التقدم.
- `assets/ui.js`: ترجمات الواجهة والأيقونات المشتركة.
- `assets/views.js`: قوالب الصفحات وعناصر العرض المشتركة.
- `assets/app.js`: ربط الواجهة بالتنقل والنسخ والتفاعلات.
- `assets/styles.css`: تصميم الحاسوب والهاتف والطباعة.
- `assets/images`: صورة مدرس المساق وشعارا الجامعة والكلية فقط.
- `downloads`: المثال بصيغتي `.kts` و`.kt`.

طباعة صفحة L01 تطبع الخطوات التسع، والطباعة من خطوة تطبع محتواها. حدود الاختبار موضحة في `TEST_REPORT.md` والمراجع في `SOURCE_NOTES.md`.

لصيانة كود الموقع وتشغيل اختباراته، راجع [دليل التطوير](DEVELOPMENT.md). هذه أدوات للمطور، ولا يحتاجها الطالب لفتح الدليل.

## إضافة محاضرة لاحقًا

في `assets/content.js` أضف سجلًا إلى `GUIDE_CONFIG.lectures` يحتوي على `id` فريد (مثل `l02`) و`code` وعنوان ووصف باللغتين و`stepIds` مرتبة. استخدم `overviewType: "standard"` للمحاضرات العادية؛ `setup` خاص بدليل L01.

أضف صفحات المحاضرة إلى `GUIDE_PAGES` بمعرّفات فريدة مثل `l02-example` واربطها بـ`lectureId` المطابق. صفحات الشرح العامة يمكن أن تستخدم `group: "lesson"`. لكل صفحة عنوان ووصف وHTML باللغتين و`num` و`sources`، و`result` اختياري. أضف كتل الأكواد إلى `GUIDE_CODES` واستخدم `data-code` لعرضها ونسخها. تظهر بطاقة المحاضرة وصفحتها والتنقل بين خطواتها من هذه البيانات، دون إضافة محاضرات فارغة للطالب.

`#overview` قائمة المحاضرات، و`#l01` مدخل المحاضرة الحالية. روابط الخطوات القديمة مثل `#kotlin-3` تعمل مباشرة، وحفظ التقدم السابق مستمر.
